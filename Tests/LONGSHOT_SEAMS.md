# 长截图灰线、常显浮窗及自动收尾（2026-10-06）

问题：用户提供的 PixPin 长图有周期性的横向灰线；采集浮窗在截图和滚动时消失；自动滚动到底需要手动完成。
根因：缩放后的分片裁切使用小数边界，clip 抗锯齿使黑底参与接缝；接缝又位于视口底缘，可能带入阴影。会话和抓屏适配器主动隐藏窗口；连续两次重复帧分支只暂停。
涉及文件：PXLongShotControl、PXLongShotFrameStore、PXLongShotSession、PXCaptureProvider、相关宿主测试和使用说明。
修改边界：长截图会话、它的可见窗口排除选项、共用的长图绘制/手势几何。不修改其他插件、HID 事件格式、偏好协议、普通截图或编辑器。
实现方案：累计接缝向上取整到同一整数像素边界并关闭 clip 抗锯齿；将裁切位置移入可靠重叠正文中部，保持新增高度等于实际位移；浮窗始终可见并仅通过排除窗口接口抓屏；手势避开浮窗；自动模式已有进展且两次短滑后均重复则导出。
运行时风险：私有窗口排除 API 在 iOS 16/17 上的实际能力、浮窗不入图、HID 路由、动态内容和设备内存峰值尚待真机验证。方法存在与返回 UIImage 不等于排除效果已验证。

## 失败及生命周期

- 可见窗口排除不可用时提示并停止采集，保持浮窗可见；不使用会摄入浮窗的普通整屏回退。
- 内存警告不再切换整屏抓取，停止新快照，待在途帧或手势释放后导出已有内容；导出时警告只释放预览。
- 已有 generation/taskID/目标 App 检查、主线程 UI、串行图像队列、锁屏取消和 Observer/Timer 清理保持有效。
- 自动模式没有任何可靠推进时，两次重复仍暂停提示页面未滚动；暂停/预览交互不触发自动结束。
- 智能和采样模式保留手动完成。自动模式的结束依据是两次确认无新增内容，不能证明宿主滚动视图的语义底部；滚动被阻断也可能保存结束。
- 对齐失败、反向画面、App 切换、锁屏仍走原有失败/暂停/取消流程，不能作为正常到底信号。

- 旧裁切逻辑：新增浅色分片非整数缩放测试失败（704 checks, 1 failure）。
- 修复后：708 checks, 0 failures。三种非整数缩放检查全宽接缝及末行无黑底；模拟视口阴影验证不在中段重复，并保持准确累计高度。
- 既有 25 段、固定头尾、反向/空白拒绝、非零原点选区、取消和预览预算测试通过。
